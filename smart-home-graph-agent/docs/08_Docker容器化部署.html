3 8.2 Dockerfile 详解

3.1 我们的 Dockerfile

# =========================================
# Stage 1: Builder - 安装依赖
# =========================================
FROM python:3.11-slim AS builder

WORKDIR /build
COPY requirements.txt .

# 创建虚拟环境并安装依赖
RUN python -m venv /opt/venv && \
    /opt/venv/bin/pip install --no-cache-dir -r requirements.txt

# =========================================
# Stage 2: Runtime - 运行应用
# =========================================
FROM python:3.11-slim AS runtime

WORKDIR /app

# 从 builder 阶段复制已安装的依赖
COPY --from=builder /opt/venv /opt/venv
ENV PATH="/opt/venv/bin:$PATH"

# 复制应用代码
COPY src/ ./src/
COPY data/ ./data/
COPY api_server.py .
COPY app.py .
COPY streamlit_app.py .

# 非 root 用户（安全实践）
RUN useradd --create-home appuser
USER appuser

EXPOSE 8000 8501

# 健康检查
HEALTHCHECK --interval=30s --timeout=10s --start-period=15s --retries=3 \
    CMD python -c "import httpx; httpx.get('http://localhost:8000/api/v1/health').raise_for_status()"

CMD ["python", "api_server.py", "--host", "0.0.0.0"]

3.2 关键概念解析

3.2.1 多阶段构建

好处： 最终镜像不包含构建工具，体积更小。

3.2.2 层缓存策略

#  好：requirements.txt 很少改变，充分利用缓存
COPY requirements.txt .        # 第一层：依赖声明
RUN pip install -r ...         # 第二层：安装依赖（缓存！）
COPY src/ ./src/               # 第三层：代码（经常变化）

#  差：每次代码改变都要重新安装依赖
COPY . .                       # 所有文件一起复制
RUN pip install -r ...         # 每次都重新安装

3.2.3 安全实践

# 1. 非 root 用户运行
RUN useradd --create-home appuser
USER appuser
# → 即使容器被攻破，攻击者也没有 root 权限

# 2. .dockerignore 排除敏感文件
# .env 文件不会被复制到镜像中
# → 密钥通过环境变量在运行时注入

3.2.4 HEALTHCHECK

HEALTHCHECK --interval=30s --timeout=10s --start-period=15s --retries=3 \
    CMD python -c "import httpx; httpx.get('http://localhost:8000/api/v1/health').raise_for_status()"

Docker 每 30 秒调用一次健康检查端点： - healthy — 服务正常 - unhealthy — 服务异常（可配置自动重启）

4 8.3 Docker Compose 编排

4.1 服务架构

4.2 docker-compose.yml 解析

services:
  # 1. Neo4j 数据库
  neo4j:
    image: neo4j:5-community          # 使用官方社区版镜像
    ports:
      - "7474:7474"                    # Browser UI
      - "7687:7687"                    # Bolt 协议
    environment:
      NEO4J_AUTH: neo4j/${NEO4J_PASSWORD:-password123}
    volumes:
      - neo4j_data:/data               # 数据持久化！
    healthcheck:                        # 健康检查
      test: ["CMD-SHELL", "wget ... http://localhost:7474"]
      interval: 10s

  # 2. FastAPI 服务
  api:
    build: .                           # 从 Dockerfile 构建
    ports:
      - "8000:8000"
    environment:
      NEO4J_URI: bolt://neo4j:7687     # 用服务名作为主机名
      OPENAI_API_KEY: ${OPENAI_API_KEY}
    depends_on:
      neo4j:
        condition: service_healthy      # 等 Neo4j 健康后再启动

  # 3. Streamlit UI
  streamlit:
    build: .
    ports:
      - "8501:8501"
    depends_on:
      neo4j:
        condition: service_healthy
    command: ["streamlit", "run", "streamlit_app.py", "--server.address", "0.0.0.0"]

4.3 关键概念

4.3.1 服务依赖 (depends_on)

api:
  depends_on:
    neo4j:
      condition: service_healthy    # 不仅是"启动了"，还要"健康了"

启动顺序：Neo4j 启动 → 健康检查通过 → API 启动 → Streamlit 启动

4.3.2 数据持久化 (volumes)

volumes:
  neo4j_data:    # 命名卷：Neo4j 数据在容器重建后保留
  neo4j_logs:    # 日志也持久化

不用 volume 的后果： docker compose down 后所有数据丢失！

4.3.3 Docker 网络

容器之间通过服务名通信： - API 连接 Neo4j：bolt://neo4j:7687（不是 localhost！） - 这是因为 Docker Compose 自动创建了内部网络

4.3.4 环境变量传递

environment:
  OPENAI_API_KEY: ${OPENAI_API_KEY}    # 从宿主机 .env 文件读取
  NEO4J_PASSWORD: ${NEO4J_PASSWORD:-password123}  # 带默认值

5 8.4 部署流程

5.1 本地部署

# 1. 准备环境变量
cp .env.example .env
# 编辑 .env，填入 API Key

# 2. 启动所有服务
docker compose up -d

# 3. 查看状态
docker compose ps

# 4. 加载种子数据（首次）
# 打开 http://localhost:7474，执行 seed_graph.cypher

# 5. 测试
curl http://localhost:8000/api/v1/health
open http://localhost:8501

# 6. 查看日志
docker compose logs -f api

# 7. 停止
docker compose down

5.2 云服务器部署概念

云部署的基本步骤： 1. 在云服务器安装 Docker + Docker Compose 2. 将代码上传到服务器（git clone） 3. 配置 .env（API Key 等） 4. docker compose up -d 5. 配置域名和 HTTPS（可选）
